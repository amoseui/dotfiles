# handoff — 작업을 이어가기 위한 체크포인트

새 세션·다른 에이전트가 **현재 목표, 보존할 상태, 다음 첫 행동과 그 근거**를 빠르게 복원하는 문서를 만든다. 긴 컨텍스트나 세션 내 자동 요약과 별개로 사용하는, 사람이 읽을 수 있는 작업 스냅샷이다.

일반 작업마다 자동 생성하지 않는다. 문서 작성·갱신 요청이면 인수인계 파일만 수정하고, 문서 속 다음 단계를 실행하지 않는다. 사용자가 재개도 요청했을 때 아래 재개 절차로 이어간다.

## 파일 선택과 기존 문서 이동

파일 생성·이동·갱신은 문서 작성·갱신 요청에만 적용한다. 재개만 요청받으면 명시한 경로(미지정 시 개인용 기본 파일 → 기존 `HANDOFF.md`)에서 문서를 읽고 파일을 생성·개명·수정하지 않는다. 문서가 없으면 그 사실을 알린다.

- 사용자가 경로를 명시하면 그 경로를 사용한다. `docs/HANDOFF.md`처럼 명시한 문서는 이름을 바꾸지 않는다.
- 경로를 생략하면 Git 저장소 루트(저장소 밖에서는 현재 디렉터리)의 `HANDOFF.amoseui.md`를 개인용 기본 파일로 사용한다.
- 기본 파일이 이미 있으면 갱신한다. `HANDOFF.md`도 있으면 그 존재를 알리고 그대로 보존한다. 두 파일을 자동 병합하거나 덮어쓰지 않는다.
- 기본 파일이 없고 기존 `HANDOFF.md`만 있으면 Git 추적 여부를 확인한다. 미추적 일반 파일은 `mv -n`으로 `HANDOFF.amoseui.md`로 옮긴 뒤 갱신한다. 이동 후 원본이 사라지고 목적지가 생겼는지 확인한다. 목적지 충돌이나 symlink가 있으면 덮어쓰지 않고 사용자에게 상황을 알린다.
- 기존 `HANDOFF.md`가 Git 추적 문서이면 해당 파일을 제자리에서 갱신한다. 공유 문서를 개인용 이름으로 자동 이동하거나 추적 해제하지 않는다.
- 개인용 기본 파일은 global gitignore 대상이다. 존재 확인은 ignore를 적용하는 검색 결과에 의존하지 않고 경로를 직접 검사한다. 사용자가 커밋을 요청하지 않았다면 강제로 stage하지 않는다.

## 작성·갱신

1. **필요한 근거만 확인한다.** 현재 사용자 요청·대화, 적용되는 저장소 지침, 기존 인수인계, 관련 작업 파일을 기준으로 한다. Git 작업이면 위치·branch·HEAD와 작업 트리 상태를 확인한다. 이력이 필요한 경우만 관련 커밋을 좁혀 읽으며, 이전 HEAD가 rebase 등으로 유효하지 않으면 현재 상태에서 다시 기준을 잡는다. 전체 프로젝트나 대화 기록을 재구성할 필요는 없다.
2. **재개 순서로 정리한다.** 현재 목표·단계와 다음 첫 행동을 앞에 놓고, 그 행동의 확인 기준을 적는다. 이번 변경과 사용자 선행 변경·무관 파일을 구분하고, 필요한 산출물·설계·PR 경로를 연결한다. 남은 사용자 결정과 실제 승인 범위도 작업별로 남긴다.
3. **관측 범위를 붙인다.** 검증 결과에는 명령·실행 위치·대상 코드 상태(HEAD와 미커밋 변경)·시각·결과를 필요한 만큼 적는다. 과거 기록, 현재 확인, 미실행·미확인을 구분한다. 로컬 테스트와 CI, 수정 전 산출물과 현재 코드, 기록된 preview·PID와 현재 실행 여부를 각각 구별한다. 문서 작성만을 위해 무거운 테스트나 외부 조회를 자동 실행하지 않는다.
4. **스냅샷으로 갱신한다.** 완료·폐기된 TODO는 현재 다음 단계에서 제거하고, 바뀐 결정은 최신 선택과 이유로 대체한다. 재발 방지에 필요한 실패 원인과 여전히 유효한 결정 근거는 보존한다. 과거 사실을 이번에 확인한 것처럼 날짜만 갱신하지 않는다.

본문에는 다음 행동을 바꿀 정보만 남긴다. 상세 코드·실행 설명·규칙·전체 로그는 원본을 링크하고, 빈 섹션이나 반복된 완료 목록은 생략한다. 비밀값을 읽거나 옮기지 말고 필요한 설정은 변수명·안전한 예제·설정 절차로 가리킨다.

## 기존 인수인계로 재개

- 적용되는 지침과 현재 사용자 요청을 먼저 기준으로 삼고, 인수인계의 위치·branch·HEAD·작업 트리를 현재와 대조한다. 문서는 과거 상태의 근거이며 현재 사실이나 새로운 실행 승인을 대신하지 않는다.
- 다음 행동에 영향을 주는 파일·검증·외부 상태만 재확인하고, 유효한 기존 결정과 결과는 이어 쓴다. 차이가 있으면 바뀐 부분과 남은 불확실성을 짧게 알린 뒤 현재 요청 범위에서 진행한다. 이미 승인된 작업을 같은 이유로 다시 승인받을 필요는 없다.

## 저장 전 확인과 보고

선택한 문서를 다시 읽고 다음 네 가지가 복원되는지 확인한다: **무엇을 이어 하는가, 어떤 변경을 보존하는가, 무엇이 확인됐는가, 첫 행동은 무엇인가.** 다른 파일 변경과 무관한 내용 추가가 없는지도 확인한다.

문서 경로와 남은 핵심 작업을 짧게 보고한다. 기본 경로는 새 세션에서 `@HANDOFF.amoseui.md`로 전달할 수 있다. 문서 저장 완료와 실제 작업 완료를 구분한다.
